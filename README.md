# eGift

**eCash, wrapped into a link.** Pick a wrapper, put XEC inside (and, if you like, one token or NFT), send the link. Whoever opens it takes the money home to their own wallet.

Site: <https://egift.cash> · Licence: MIT · Status: **beta — use small amounts.**

## How it works

- **The link is the gift.** A gift link carries a 16-byte secret after the `#`. The browser turns it into a key and an eCash address; the giver funds that address from their own wallet (Cashtab). Whoever holds the link can sweep the address to a wallet of theirs.
- **No server, no account.** The site is static files. The part of a link after `#` never reaches any server. Nothing is stored anywhere except, by your own press, a short record in your browser.
- **The chain is read through public Chronik nodes** listed in `src/core/chain/chronik.ts`. The site's Content-Security-Policy allows those hosts and nothing else.
- **Wrappers** are data: layered SVG, a timeline, a theme and a short tune, checked by a validator. Some wrappers have a price; it is paid to the project inside the transaction that funds the gift, and a gift whose wrapper was not paid for opens in the default wrapper. The money in a gift is never held back.

## What you should know before using it

- **Anyone with the link can take the gift**, including a chat app or a person the link was forwarded to. A lost link is a lost gift: nobody can recover it.
- **A gift link is not a wallet.** Take the gift home soon.
- A gift can be locked with a riddle: the answer is needed, together with the link, to open it.
- How it is built to keep a gift safe, and what others can see, is in [`docs/security.md`](docs/security.md).

## Run it

Node 22.22 and pnpm 10.

```bash
pnpm install
```

```bash
pnpm dev
```

The dev server is at `http://localhost:5183`. Add `?demo` to the address to try everything with pretend money and no network.

```bash
pnpm test
```

```bash
pnpm build
```

`pnpm build` checks every wrapper picture, type-checks, bundles into `dist/`, and writes one page per wrapper so that a shared link shows that wrapper's card.

## Layout

| Path | What |
|---|---|
| `src/core/` | Keys, links, transactions, the chain client. No DOM. |
| `src/stage/` | The wrapper format, its validator and the player. |
| `src/wrappers/` | The wrappers that ship, their prices, their tunes. |
| `src/ui/` | Screens, sound, the capsule. |
| `src/i18n/` | Thirteen languages. Vietnamese and English are the source; the others are machine translations. |
| `public/wrappers/` | Wrapper art (generated by `scripts/art/*.gen.mjs`). |
| `public/og/` | Share cards (drawn by `scripts/og-cards.mjs`). |
| `docs/` | Security notes. |
| `vendor/` | Pinned copies of the eCash libraries the app is built with. |

## Promises the tests keep

- A link that was sent keeps opening: a shipped wrapper id is never removed or renamed, and the same link always names the same address (`src/wrappers/forever.test.ts`).
- No key exists before "Create" is pressed; the key never goes to storage, a request, a title or a log.
- Text from a link or from the chain reaches the page as text only.
